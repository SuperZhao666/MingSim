## 3. 最大架构冲突：两套世界推进

目前并存：

```text
旧路径：TurnNumber → ResolveTurn → AdvanceTurn
新路径：CurrentTime → RealtimeSimulationRuntime.Advance → Scheduled Events
```

原策划最终明确采用可暂停实时，因此不能继续向两条路径同时加玩法。

### 裁决

- `GameTime + Scheduler + 单写者` 成为唯一主运行路径；
- `WorldVersion` 取代 `TurnNumber` 的并发/过期语义；
- 旧 `TurnNumber` 暂时只用于读取旧内容/测试，设置明确删除里程碑；
- `ResolveTurn` 中的临时工作区、不变量和“全有或全无”迁入命令/到期批次 Commit；
- Industry 的“每回合生产一次”以后改为月度/排程结算；
- 不立即删除旧实现，先用特征测试锁住已有行为，再渐进迁移，最后删除。

## 4. 当前快照/提交的关键缺口

现有 `TurnOrchestrator` 顺序是：

```text
WorldStore.Commit
→ AuditJournal.Append
→ SnapshotStore.Promote
```

内存适配器中能演示流程，但真实崩溃时三步不是同一事务。目标必须改为：

```text
SQLite 一个事务：状态 + 外部 InputJournal（若有）/ActionOutcome + EventJournal + Commit
→ 成功后发布内存版本
→ 周期 Snapshot 另走“写临时→真实加载→验证→切指针”
```

Snapshot 不属于每条命令的同步事务；Current State、对应的外部 InputJournal 或 ActionOutcome、EventJournal 与 Commit 属于同一正式事务。空小时可跳过，但权威时间实际推进到动作/暂停/目标点时必须提交时间状态。

当前依赖也尚未达到目标图：`Ming.Persistence` 仍引用 Application/Domain，没有引用 Simulation；`Ming.Agents` 仍只引用 Domain。实现阶段要移动/新增端口并更新 `.csproj` 引用，而不是只改文档上的箭头。

## 5. 当前状态哈希缺口

已有 `StateHasher` 是好雏形：对地图、库存、军队、设施、机构、权限和人物排序哈希。

目标还需包括：

- `CurrentTime`；
- `WorldVersion/CommitId`；
- Scheduler 队列和稳定序号；
- 随机流状态；
- Decree/Document/Shipment；
- 人物关系、目标、记忆/Belief 中会影响未来结果的部分；
- 动态地图控制/路线状态；
- 内容/规则版本。

当前哈希不包含 `CurrentTime`，所以两个不同日期但其他字段相同的世界可能得到相同哈希；在正式重放前必须修正。

## 6. 现有实时运行时的优点与风险

### 已有优点

- `PriorityQueue`；
- `DueAt + sequence` 稳定优先级；
- 暂停和速度；
- 精确到达动作；
- UI 外的纯 C#；
- 未知调度事件不直接改状态。

### 需要改进

- 当前 Runtime 直接持有并修改 `State`，尚无统一 Command/Commit Store；
- `Advance(realElapsed)` 仍接收真实时间换算，测试核心应优先 `AdvanceTo(GameTime)`；
- 每小时 `while` 在完整世界规模需压测/可跳转优化；
- Scheduler 队列未进入存档/哈希；
- 日心跳和军队抵达逻辑塞在同一 300 行类，新增后会膨胀；
- 命令类型与旧 `WorldIntent` 分成两套；
- 事件处理后没有完整不变量与数据库事务；
- 军队在移动期间没有明确 `MovementState`，到达前是否可重复命令需定义；
- `DateTime` 当前可用，但长期应封装游戏日历/文化无关序列化。

不要立刻重写。先写覆盖现有行为的确定性测试，再沿黄金用例拆最小接口。

## 7. 代码规模信号

当前核心手写 C# 文件大多在 10–200 行，两个热点：

- `RealtimeSimulationRuntime.cs`：约 309 行；
- `SimulationKernel.cs`：约 276 行。

这不是单凭行数就必须拆，但两者都是“每加一种命令就增长一个分支”的变化热点。统一实时路径时建议：

```text

每个真实业务系统
→ 用小型具体规则处理自己的命令/到期动作
```

不要把每个动作拆成 18 个类；先按 Logistics、Military、Time 三个真实职责分开即可。
