# 宁远急饷 MVP 来源账本

> 这是一份“先把证据边界写清楚”的最小账本，不是已经完成的历史考证。它把当前内容分成：本项目取舍、玩法设计值、原稿线索、待外部史料验证四类，防止代码把暂定数字伪装成史实或原稿最终定案。

## 1. 怎么读

| 标签 | 含义 | 能否直接写入正式历史内容 |
| --- | --- | --- |
| `DECIDED_BY_ADR` | 原稿有多个候选，本项目为完成 MVP 作出的取舍 | 可以，但必须保留 ADR/版本与重评条件 |
| `BASELINE` | 原稿后期与产品宪法一致的当前基线 | 可以进入设计，历史细节仍需各自查证 |
| `DESIGN` | 为平衡和测试暂设的玩法参数 | 可以，必须明确不是史实数字 |
| `SOURCE-NOTE` | 原策划研究稿中的线索 | 只能作为继续查证的入口 |
| `OPEN` | 尚未找到足够可靠证据或尚未裁决 | 不得伪装成确定事实 |

原始研究稿保存在本地且未随公开仓库发布，共 16,691 行，SHA-256 `AF5825C4183E32A18A2ED0415C9D131E3FEB8A3FBAEDCFBB48CE77AA88632D61`。研究稿本身包含多轮讨论和部分不可复用引用，所以“稿中写过”不等于“史实已证实”。正式外部来源按[16-历史内容与证据生产规范](16-历史内容与证据生产规范.md)补录。

## 6. P0 必须先补的外部证据

按阻塞开发的先后顺序：

1. 1629 年场景的具体起止背景，确认不会把不同年份的人物和态势拼在一起；
2. 北京/通州—山海关—宁远的陆路节点、典型时长与运力口径；
3. 登莱海运作为备选方案在该时期的可行性和限制；
4. 户部、兵部、督师/巡抚、前线将领在粮饷事务中的权限和文书链；
5. 关键人物的任职起止、关系和可引用传记材料；
6. 粮、银、日耗、欠饷等数字至少给出来源、时间、地区、单位和不确定范围。

## 7. 关闭一个 `OPEN` 的标准

一个条目只有同时满足以下条件才能从 `OPEN` 改为 `FACT` 或 `INTERPRETATION`：

- 来源可重新打开，书目信息或稳定链接完整；
- 原文确实支持该主张，不是标题相似；
- 年份、地点、对象和单位相符；
- 直引不超过必要长度，主要记录释义和页码；
- 若来源冲突，保留双方及采用理由；
- 内容审校与玩法设计分开签字：史实证据成立，不代表一定进入 P0。

## 8. 当前结论

现在可以安全实现的是：**一个明确标为设计原型的 1629 宁远运粮闭环**。现在还不能安全宣称的是：具体人物名单、路线精确天数、库存和损耗都是历史原值。先守住这条边界，后续内容扩张才不会把研究笔记变成不可追溯的“游戏事实”。
