# ADR-004：首个玩法切片采用 1629 宁远急饷

状态：Accepted  
日期：2026-08-13

## 背景

原始策划没有最终统一首发年份：1641 被明确写成“最小可行场景建议”（3907–3923）；1629 北京—辽东只是垂直切片示例（12248–12304）；`ming_1627` 只是目录示例（13498–13505），没有说明完整内容范围。项目若不作本地裁决，就会同时制作多套人物、地图和财政数据。

## 决定

本蓝图暂定第一个玩法切片采用 1629 年前后的“宁远急饷”：6–7 个北京—辽东/登莱节点，首轮设计为 90 个游戏日，先证明政令、人物机构、银粮、运输、风险、信息、反馈和存档闭环。

这是 `DECIDED_BY_ADR + DESIGN`，不是“原文最终定案”。精确日期、人物、路线和数值保持 `OPEN`，必须先过 Source Ledger 与纸面/数值试玩；若核心前提不成立，本 ADR 可在编码场景数据前被替换。

当前 `content/ming_1627` 在内容迁移任务完成前不立即重命名。

## 原因

- 原稿后期多次使用北京—山海关—宁远/锦州、粮运和实时运输作为设计示例（12248–12304、9483–10520、15416–15483）；
- 后勤能同时验证几乎所有核心架构边界；
- 地图和角色规模足够小，个人可以完成；
- 结果有明确但不单一的成败评价。

## 代价

- 全国行政、陕西、江南、完整外交和技术暂不呈现；
- 需要重新核对 1629 的史实开局数据；
- 现有 1627 JSON 将经历一次受控内容迁移。

## 被否决方案

- 直接把 `ming_1627` 目录当首发决定：目录示例没有说明场景范围，证据不足；
- 1641 最小场景建议：是有效候选，但财政、民变、战争耦合更高，先放入后续比较而非声称被原文否定；
- 无历史日期纯技术 Demo：可用于 M1/M2 测试，但不足以验证最终玩法和内容生产。

## 何时重新评估

在编写场景数据前，若 Source Ledger 证明 1629 无法支持设计的关键角色/路线，或纸面/数字原型试玩明确显示另一年份更好，可用新 ADR 取代。

## 验证

- 场景 Source Ledger；
- 6–7 节点地图；
- “运粮到宁远”黄金用例；
- 30 分钟可用性测试；
- 60–90 日混合结局。
