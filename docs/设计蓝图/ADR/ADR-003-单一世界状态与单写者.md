# ADR-003：单一世界状态与 Simulation 单写者

状态：Accepted  
日期：2026-08-13

## 背景

策划源于“奏疏称完成但底层没有完成”“工厂和产能两套数据不一致”“存档恢复半失败”等问题。UI、AI、线程和数据库若各自修改状态，会不断产生真假冲突。

## 决定

`WorldState` 表示唯一已提交世界；只有 Simulation 单写者能修改它、推进时间、分配事件序号和提交事务。UI、Agent 和后台任务只能发 Command/Intent 或读取不可变 ReadModel/Snapshot。

## 原因

- 一个事实只有一个可写来源；
- 避免并发写、锁和跨线程半状态；
- 所有结果可经过权限、不变量和事务；
- 重放与故障恢复有明确版本边界。

## 代价

- 所有写操作必须排队；
- 长计算不能阻塞单写循环，需拆成纯计算或后台建议后再提交；
- 查询视图必须显式派生。

## 被否决方案

- UI/模块各自拥有状态并同步：同步本身制造第二真相；
- 多线程直接锁 `WorldState`：难以保证顺序、随机和事务确定性；
- LLM 直接工具写库：概率输出越过规则防火墙。

## 何时重新评估

只有正式多人服务器经过测量必须按独立世界/区域分片时重评；每个分片内部仍应保持单写者。

## 验证

- 架构依赖检查；
- 并发提交测试；
- 模型“已完成”文本不改变哈希；
- UI 只能获得 ReadModel；
- SQLite 与内存版本一致。
