# ADR-001：V1 采用模块化单体与现有工具链

状态：Accepted  
日期：2026-08-13

## 背景

原始策划早期出现 PostgreSQL、Redis、Kafka、Temporal、Orleans、微服务和云存档等商业级方案；后期明确收缩为个人能完成的本地单机项目。当前工程和外置工具链已经实际具备 .NET 10 与 Godot 4.6 .NET。

## 决定

V1 使用一个本地进程内的模块化单体：Godot 4.6 .NET + C#/.NET 10 + SQLite WAL。模块通过进程内强类型接口交互，首版没有服务器、微服务、Redis、Kafka、Temporal 或 Orleans。

## 原因

- 最少部署、通信和调试代码；
- 同一语言覆盖模拟和 UI 适配；
- 核心可无 Godot 独立测试；
- SQLite 满足单机事务和可移植存档；
- 清楚模块边界仍保留未来拆分可能。

## 代价

- 单个进程需要谨慎控制 UI、模拟和后台任务的线程边界；
- SQLite 同时只允许一个写者；
- 不提前提供联机和云端横向扩展。

## 被否决方案

- 微服务：没有当前负载或多人需求为其复杂度付费；
- Unity：当前 Godot 原型和工具链已存在，迁移无玩法收益；
- Rust/C++ 核心：在未发现 C# 性能瓶颈前增加语言/ABI 成本；
- PostgreSQL：单机部署和存档迁移成本高于当前收益。

## 何时重新评估

只有 Profiling 证明单进程/SQLite 无法满足已完成纵切的明确性能目标，或正式批准多人服务器范围时重评。

## 验证

- 一个本地进程完成纵切；
- Domain/Simulation 不引用 Godot/SQLite/模型 SDK；
- headless 和 Godot 两条真实入口通过。
