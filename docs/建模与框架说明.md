# MingSim 建模与框架说明

## 1. 先理解“对象”是什么

这里的对象不是为了让代码看起来像现实世界，而是为了明确谁拥有哪一类数据、谁允许修改哪一类数据。

| 对象 | 负责回答的问题 |
| --- | --- |
| `WorldState` | 现在这个世界到底是什么状态？ |
| `CharacterState` | 这个人是谁、会什么、承受了多少压力？ |
| `InstitutionState` | 这个机构能提供哪些能力？ |
| `CapabilityGrant` | 这个人现在有没有权限调用某项能力？ |
| `WorldIntent` | 某个角色想做什么？ |
| `Decree` | 玩家/皇帝的正式政令是什么、范围和期限是什么？ |
| `SimulationKernel` | 这个行动是否符合规则，执行后世界会变成什么？ |
| `DomainEvent` | 已经确认发生了什么？ |
| `SnapshotPreparation` | 如何安全地保存一份完整世界？ |

最重要的区分是：

- “工部尚书提出建厂”是 `BuildFacilityIntent`；
- “国库扣了钱并登记了工坊项目”才是 `FacilityProjectStarted`；
- “工坊已经生产出多少燧发枪”由自动生产系统根据真实工坊状态计算。

模型的语言不能替代后两者。

## 2. 为什么要有临时工作区

一个回合可能同时有多个角色提案。内核先复制一份冻结状态，在复制品上依次归并：

```text
冻结状态
  ├─ 工部提案：花 50,000 两建工坊
  └─ 兵部提案：消耗 1,000 支燧发枪改编 1,000 人
          ↓
      临时工作区
          ↓
  任意一项失败？——是——> 整个工作区丢弃，原世界不变
          ↓ 否
      不变量检查
          ↓
      生成快照并提交
```

这解决了“前半个动作成功、后半个动作失败，存档却留下半截结果”的问题。

## 3. 权限为什么不写在 Agent 里

Agent 说“我是兵部，所以我能改编军队”并不算授权。授权属于世界状态的一部分，应该由 `CapabilityAuthorizer` 根据：

1. 调用者是否是已存在角色；
2. 是否拥有对应能力；
3. 是否覆盖目标资源；
4. 是否已经过期；

统一判断。这样以后换成玩家按钮、规则 AI 或云端 LLM，安全边界都一样。

## 4. 注释的阅读顺序

如果你是第一次接触这类项目，建议按下面顺序读：

1. `src/Ming.Domain/WorldState.cs`：先看世界装了哪些大类状态；
2. `src/Ming.Domain/Intents/WorldIntent.cs`：看“想做什么”和“已经做成”有什么区别；
3. `src/Ming.Simulation/Simulation/SimulationKernel.cs`：看一项行动怎样被校验和应用；
4. `src/Ming.Application/Workflows/TurnOrchestrator.cs`：看回合怎样保存；
5. `src/Ming.Agents/Runtime/AgentRuntime.cs`：看代理为什么只能提案；
6. `src/Ming.Cli/Program.cs`：看所有模块怎样拼成一次演示。

## 5. 目前刻意没有做的事

- 没有把 LLM 接进确定性结算路径；
- 没有把 SQLite、Redis、Kafka、Orleans、Temporal 引入第一版；
- 没有把每个 NPC 立即实现成昂贵的独立大模型调用；
- 没有把 Godot Node 当成世界实体；
- 没有把历史人物名称硬编码进规则代码。

## 6. 地图为什么单独建模

地图不是一张“画出来的图片”，而是两类数据的组合：

1. `Ming.Domain.Map.MapDefinition`：省份编号、名称和邻接关系，属于可以参与规则校验的静态拓扑；
2. Godot/地图工具资源：多边形坐标、颜色、标签位置和底图，属于表现层数据。

这样做的好处是：地图换皮不会改变仿真结果，命令行也能在没有 Godot 的情况下检查省份引用。当前 `content/ming_1627/world.json` 已经使用 `map.provinces` 保存最小拓扑；未知邻接、自环和重复邻接会在加载时直接拒绝。

开源项目的源码考古、许可证和“哪些能复用、哪些只借鉴”的记录见：[开源架构考古与复用边界](开源架构考古与复用边界.md)。

这些不是遗漏，而是为了先把最重要的边界做实。
